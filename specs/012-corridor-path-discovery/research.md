# Phase 0 Research: Gradual Corridor Path Discovery and Adaptive Survey

**Feature**: `012-corridor-path-discovery` | **Date**: `2026-11-19` | **Spec**: [spec.md](file:///home/remi/Projects/Intent-Swarm-Commander/specs/012-corridor-path-discovery/spec.md)

## Decision 1: Sub-500 ms Edge 3D Corridor Visual Analysis (`src/edge/vision/corridor_analyzer.py`)

- **Decision**: Implement `CorridorVisualAnalyzer` in `src/edge/vision/corridor_analyzer.py` combining deterministic OpenCV (`cv2` + `numpy`) 5×3 spatial-grid free-space and structural-clearance analysis with `YoloEInference.detect(frame, target_class=None)` and cached `EdgeTargetMatcher` classification (`<1 ms` cached lookup). Specifically, each incoming frame is evaluated for:
  - Visual confidence and health: Laplacian variance (sharpness/blur), mean/stddev luminance (darkness/overexposure), and inter-frame mean absolute difference across consecutive captures (frozen-frame detection).
  - 5×3 spatial-grid structural occupancy (`5` horizontal azimuth sectors spanning left-wide through right-wide × `3` vertical elevation bands: upper/ceiling, middle/cruise, lower/floor) derived from Sobel/Canny gradient density, edge continuity, and vertical horizon/vanishing-corridor openness.
  - Open passage candidate extraction: horizontal azimuth offset (`-90°..+90°`), vertical elevation bias (`climb` / `level` / `descend` for low overhangs, ramps, or multi-level openings), estimated lateral corridor width, estimated vertical headroom, intersection/fork branch detection (`>=2` separated navigable opening peaks), and dead-end/blocked-passage classification (`visual_openness < threshold`).
  - Integrated `YoloEInference` + `EdgeTargetMatcher` object discrimination: identifies unexpected corridor hazards (e.g., poles, debris, barriers, blocked passages) for avoidance/halting while flagging objects matching `intelligence_focus` for highlighted capture in the intelligence output (`FR-016`) without pausing on HITL gates.
- **Rationale**:
  - Satisfies the clarified `<=500 ms` per-snapshot trajectory latency SLA (`SC-007`) deterministically on Raspberry Pi 5 and container CPU nodes (~30–120 ms per frame end-to-end) without external network round-trip jitter.
  - Naturally detects dead ends, enclosed starts, corridor intersections/forks (`FR-011`), curves, L-turns, S-bends, width variations, low overhangs, and sloped elevation changes (`FR-006`, `FR-021`), and degrades safely on dark, blurry, or frozen video (`FR-015`).
  - Uses existing `opencv-python-headless`, `numpy`, `ultralytics`, and `google-genai` dependencies already in `pyproject.toml` with unconditional top-level imports (Constitution VII) and zero fallback algorithms or mocks in `src/` (Constitution VI & VII).
- **Alternatives considered**:
  - Calling Gemini VLM synchronously on every in-flight frame to steer the drone: rejected because 400–1500 ms cloud RTT breaks the `<=500 ms` SLA (`SC-007`) and fails under degraded/DDIL links.
  - Introducing an external ROS 2 SLAM / OctoMap perception stack: rejected because it adds heavy unapproved runtime dependencies outside `pyproject.toml` and exceeds the single-Pi edge compute footprint.

## Decision 2: 3D Corridor Discovery State Machine & Relative Local Navigation (`src/edge/navigation/corridor_survey.py`)

- **Decision**: Create a dedicated `CorridorSurveyController` in `src/edge/navigation/corridor_survey.py` separate from `FlightController` (`src/edge/navigation/flight_controller.py`), implementing a deterministic state machine:
  `initializing` → `initial_look_around` → `outbound_discovery` ↔ (`boundary_hold` / `turn_look_around`) → `returning` ↔ `return_blocked_hold` → `completed` / `completed_holding`, plus terminal/override states `impassable_start` and `emergency_hold`.
  - **Origin-Anchored Local 3D Frame**: Anchor an origin `(origin_lat, origin_lon, origin_abs_alt_m, origin_rel_alt_m)` at survey start and map local 3D relative coordinates `(x_east_m, y_north_m, z_rel_m)` to/from MAVSDK GPS + relative altitude telemetry. Every accepted 3D movement step records a `PathBreadcrumb3D` and accumulates 3D path length `sqrt(dx^2 + dy^2 + dz^2)` (`FR-008`, sharp-turn/loop edge case).
  - **Initial 360° Look-Around (`FR-002`, `FR-003`, `SC-002`)**: Hover at origin and yaw across 8 discrete headings (`0°`, `45°`, `90°`, `135°`, `180°`, `225°`, `270°`, `315°`), capturing and uploading all 8 panoramic snapshots before clearing any forward movement. If no navigable opening passes safety confidence across the 360° sweep, transition to `impassable_start`, hold safely at origin, and notify the operator.
  - **Rolling Flight, Cleared-Segment Boundaries & 5 s Failsafe (`FR-005`–`FR-007`, `FR-015`, `SC-004`, `SC-007`)**: Advance continuously along the currently cleared 3D trajectory segment while periodically capturing snapshots. If the drone approaches the cleared-segment horizon before the next edge trajectory instruction arrives—or if edge analysis requests extra visual context at a sharp corner/junction—decelerate to `boundary_hold` / `turn_look_around`. If no valid edge update resumes within `5.0 s` while holding at a boundary (or if visual confidence remains degraded after re-capture), automatically transition to failsafe reverse-path return along the verified `PathBreadcrumb3D` sequence (or hold safely with alert if return cannot be guided).
  - **3D Altitude Envelope & Endurance-Bounded Distance (`FR-009`, `FR-021`)**: Clamp all vertical trajectory adjustments strictly to configurable `[min_altitude_m, max_altitude_m]` bounds (refusing any adjustment violating the configured envelope). Support arbitrarily large positive target distances without a fixed upper cap by computing a dynamic safe-return battery reserve based on current `battery_pct` and traversed path distance (`discovered_path_length_m`), transitioning proactively to `returning` when the reserve threshold is reached.
  - **Reverse-Path Return & Two-Tier Overrides (`FR-010`, `FR-018`)**: Replay the verified `PathBreadcrumb3D` list in reverse order using MAVSDK `goto_location(lat, lon, target_abs_alt, reverse_heading)` while continuing return-leg snapshot monitoring to adjust around minor dynamic obstructions or enter `return_blocked_hold` with an operator alert if completely blocked. Expose `recall()` (immediate transition to `returning` + partial report) and `emergency_abort()` (immediate MAVSDK `action.hold()` → `emergency_hold`).
- **Rationale**: Keeping `CorridorSurveyController` decoupled from `FlightController` prevents regressions to Feature 011 obstacle avoidance and existing Point-A-to-Point-B missions while giving Feature 012 clean, testable 3D breadcrumb and failsafe semantics.
- **Alternatives considered**:
  - Embedding corridor discovery into `FlightController._navigation_loop()`: rejected because Feature 011 relies on global waypoint/target-intercept loops incompatible with breadcrumb-based 3D retracing and 8-heading 360° start sweeps.
  - Using MAVSDK `return_to_launch()` (RTL) for `"go back"`: rejected because direct straight-line RTL flies above/across corridor walls and violates the reverse-path return safety requirement.

- **Decision**:

  3. In `SmeacFacade.submit_smeac_order()`:
     - Enforce strict validation (`FR-001`, `FR-021`): reject non-positive `target_distance_m <= 0`, inverted altitude bounds (`min_altitude_m >= max_altitude_m`), and explicit `altitude_m` outside `[min_altitude_m, max_altitude_m]` with HTTP `422 Unprocessable Entity`; default omitted `target_distance_m` to `20.0` (`distance_defaulted = True`), omitted `return_to_origin` to `True`, and omitted `altitude_m` (`entry_altitude_m`) to `clamp(2.5, min_altitude_m, max_altitude_m)`; permit any positive `target_distance_m` without an upper distance cap.

  4. Extend `dispatch_edge_mission_activity` in `src/uservice/smeac/operations/process.py` to dispatch `corridor_survey` commands to `POST {endpoint_url}/corridor-survey/start` with `survey_id`, `command_id`, `drone_id = lead_scout_drone_id`, `staging_hold_drone_ids`, `entry_altitude_m`, and validated 3D/distance parameters (keeping existing `/navigate` + `/target` dispatch intact for waypoint orders). In `src/edge/api/server.py`, starting a corridor survey cancels/stops any pre-existing vision or navigation tasks on `staging_hold_drone_ids`, holds those drones safely at staging, and publishes `flight_status = "survey_staging_hold"` telemetry while launching `CorridorSurveyController` exclusively on `lead_scout_drone_id`.
  5. Introduce a clean `uservice-template` DDD domain package `src/uservice/corridor/` (`api/routes.py`, `facade/corridor.py`, `models/contract/schemas.py`, `models/storage/survey.py`, `operations/survey_service.py`) and register `"/corridor-surveys"` in `_DIRECT_PREFIXES` / pass-through checks inside `src/uservice/security/proxy.py`.
- **Rationale**: Directly implements clarified Q3=A (unified SMEAC order flow), Pass 2 Q3=A (single lead scout + staging hold), and Pass 2 Q5=C (non-positive rejection, `20 m` default, unbounded positive distance, configurable 3D bounds) while following `uservice-template` DDD layering (`Router → Facade → Operations → Storage`).
- **Alternatives considered**:
  - Creating a separate standalone command endpoint outside SMEAC: rejected per clarified Q3=A.
  - Rejecting multi-drone swarms (`drone_count > 1`) for corridor orders: rejected per clarified Pass 2 Q3=A.

## Decision 4: Full Snapshot Persistence, MQTT Provenance & Corridor Intelligence Storage (`FR-012`, `FR-014`, `FR-020`)

- **Decision**:
  1. **Every Snapshot Persisted (`FR-020`)**: In `EdgeTelemetryPublisher.publish_corridor_snapshot()`, encode and upload **every** captured look-around, outbound, hold, and return snapshot JPEG (non-empty JPEG magic bytes `\xff\xd8\xff`, max `5 MB`) to MinIO bucket `tactical-snapshots` under UUID-keyed path `projects/{project_id}/swarms/{swarm_id}/corridor-surveys/{survey_id}/drones/{drone_id}/{snapshot_id}.jpg` (or spool locally under `EdgeSpool` on link outage for lossless replay on reconnect). Snapshot TTL expiration and storage pruning are explicitly omitted as out of scope per Pass 2 Q4=B.
  2. **Canonical MQTT Provenance Envelope (`FR-014`)**: Publish all corridor survey events (`corridor_snapshot`, `corridor_trajectory`, `corridor_phase`, `corridor_report`, `corridor_override`) on the existing canonical topic `telemetry/projects/{project_id}/swarms/{swarm_id}/{drone_id}/alert` (QoS 1) via `SwarmTelemetryEvent` with `extra.command_source = "edge_corridor_survey"` (or `"operator_corridor_override"`). `is_edge_autonomous_alert()` and `EdgeAvoidanceCommand` remain dedicated to Feature 011 obstacle avoidance so existing tests and contracts stay 100% intact.
  3. **Central Ingestion, Incremental Report Materialization & Auditability (`SC-006`)**: Extend `TelemetryIngestor._persist_telemetry_and_audit()` to detect corridor survey events (`is_corridor_survey_event(event)`), persist immutable `AuditEvent` records (`actor_type=ActorType.AGENT` / `ActorType.COMMANDER`), and invoke a `corridor_survey_callback` that atomically upserts `CorridorSurvey`, `CorridorSnapshot`, `CorridorTrajectoryDecision`, and `CorridorFinding` rows in PostgreSQL. Because the intelligence state is materialized incrementally as events stream in, the final `CorridorIntelligenceReport` is queryable within milliseconds (`<<5 s`, satisfying `SC-006`).
  4. **Non-Blocking Mid-Corridor Detections (`FR-016`)**: Every `SurveyPhase` maps 1-to-1 to telemetry `flight_status = f"survey_{phase}"` (`survey_initializing`, `survey_initial_look_around`, `survey_impassable_start`, `survey_outbound_discovery`, `survey_boundary_hold`, `survey_turn_look_around`, `survey_returning`, `survey_return_blocked_hold`, `survey_emergency_hold`, `survey_completed`, `survey_completed_holding`), plus `"survey_staging_hold"` for held staging drones (`FR-019`). All satisfy `flight_status.startswith("survey_")` and never emit `"approaching"`, ensuring `main.py` `_handle_detection` never creates blocking HITL requests mid-corridor.
- **Rationale**: Guarantees zero snapshot loss (`FR-020`), leverages existing QoS 1 MQTT + `EdgeSpool` DDIL resilience + `ParquetCompactor`, and satisfies sub-5-second final report availability (`SC-006`).
- **Alternatives considered**:
  - Sampling only 2 m keyframes: rejected per clarified Pass 2 Q4=B.
  - Creating a separate MQTT topic hierarchy outside `WILDCARD_TELEMETRY_TOPIC`: rejected because it duplicates Mosquitto subscriptions and bypasses `EdgeSpool` DDIL buffering and `ParquetCompactor`.

## Decision 5: Operator Dashboard Live 3D Corridor View, Controls & XSS-Safe Rendering (`src/dashboard/`)

- **Decision**: Add a **Corridor Survey & Intelligence** panel (`#corridor-survey-panel`) to `src/dashboard/index.html` and implement its controller in `src/dashboard/js/corridor.js` wired through `src/dashboard/js/api.js` and `src/dashboard/js/main.js`.
  - **Dual-Projection Relative 3D Visualization**: Render two synchronized vector canvases built exclusively with `document.createElementNS("http://www.w3.org/2000/svg", ...)` (zero `innerHTML`):
    1. **Top-Down Plan View (`X` East vs. `Y` North meters)**: Verified corridor centerline, estimated wall/clearance envelope, origin marker, 360° look-around indicator, turns/branches, findings/hazards, live drone marker, and reverse return track.
    2. **Vertical Elevation Profile (`Path Distance m` vs. `Relative Altitude Z m`)**: Configured `[min_altitude_m, max_altitude_m]` safety ceiling/floor dashed lines, altitude trajectory line, low overhangs, and sloped segments.
  - **Lead Scout & Staging Status Badge**: Displays `lead_scout_drone_id`, `staging_hold_drone_ids`, active `phase`, `surveyed_distance_m / requested_distance_m`, and early-termination/completion outcome.
  - **Full Snapshot Replay Filmstrip & Findings List**: Displays every persisted snapshot fetched securely via authenticated backend BFF proxy (`GET /api/v1/swarms/{swarm_id}/corridor-surveys/{survey_id}/snapshots/{snapshot_id}/image` using `fetchSnapshotBlobUrl` with object-URL revocation on refresh), structural features, unexplored branches, and snapshot-linked decision audit trail.
  - **Two-Tier Operator Override Controls**: Dedicated **Recall Scout (Reverse Return)** button and **Emergency Abort (Hold in Place)** button backed by an explicit in-page `<dialog>` confirmation prompt (never native `confirm()` or `alert()`, adhering to `mandatory-secure-web-skills`).
- **Rationale**: Dual-projection SVG clearly conveys both horizontal turns/branches and 3D elevation adaptation without relying on GPS tile maps (unavailable in relative/indoor corridors) or external CDN libraries.
- **Alternatives considered**:
  - Plotting relative corridor segments on Leaflet geographic tiles: rejected because relative local coordinates in GPS-denied spaces and vertical elevation profiles cannot be meaningfully inspected on a 2D geographic tile map.
  - Loading Three.js from an external CDN: rejected due to external asset/CSP/SRI overhead when dual-projection SVG is lighter, deterministic in Playwright tests, and completely self-hosted.

## Decision 6: Zero-Mock Multi-Shape Corridor End-to-End Verification (`scripts/virtual_cam_server.py` & `tests/e2e/prod_corridor_survey.spec.js`)

- **Decision**: Extend `scripts/virtual_cam_server.py` (which resides strictly in `scripts/`, outside `src/`) with a pose-aware 3D corridor perspective generator (`mode = "corridor_scene"`) that subscribes directly to local Mosquitto MQTT telemetry (`telemetry/projects/+/swarms/+/+/navigation` and `telemetry/projects/+/swarms/+/+/alert`, configured via `MQTT_BROKER_HOST` / `MQTT_BROKER_PORT` + `depends_on: [mosquitto]` on `virtual_cam` in `docker-compose.yml`). This lets `corridor_scene` render live pose-driven 3D perspective frames automatically as the PX4 SITL drone moves while keeping `src/edge/` 100% simulation-unaware, with `POST /pose/{drone_id}` retained as an optional direct test override. Supported selectable corridor geometries:
  - `straight_20m`: straight passage (`>=25 m`) with side texture markers;
  - `l_turn_20m`: straight `10 m` entry + sharp `90°` right turn continuing `15 m` + optional interior target object;
  - `s_bend_overhang_20m`: curved S-bend with a low-ceiling overhang forcing a safe altitude dip within `[min_altitude_m, max_altitude_m]`, plus return climb;
  - `dead_end_12m`: straight passage terminating in a solid brick/wall dead end at `12 m`;
  - `branch_junction_20m`: T-junction / fork at `8 m` with primary continuation + logged side branch;
  - `enclosed_start`: all 360° bearings blocked at origin (validates `impassable_start`).
  During `tests/e2e/prod_corridor_survey.spec.js`, `src/edge` connects to `http://virtual_cam:8091/stream/{drone_id}` and real PX4 SITL via MAVSDK, runs real `CorridorVisualAnalyzer`, `YoloEInference`, `EdgeTargetMatcher`, `CorridorSurveyController`, real MinIO snapshot uploads, real Mosquitto MQTT events, real `src/uservice` PostgreSQL persistence, and real Playwright dashboard verification (zero mocks in `src/`).
- **Rationale**: Satisfies `FR-017` and clarified Q5=A deterministically and reproducibly across all corridor shapes (straight, L-turn, S-bend + overhang, dead-end, junction, blocked start) with zero mock components in `src/`.
- **Alternatives considered**:
  - Unit tests only: rejected by `FR-017`.
  - Building custom 3D SDF corridor worlds in Gazebo: rejected per clarified Q5=A due to high world-authoring complexity and GPU rendering variance in headless CI.
