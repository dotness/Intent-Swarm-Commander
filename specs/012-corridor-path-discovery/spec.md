# Feature Specification: Gradual Corridor Path Discovery and Adaptive Survey

**Feature Branch**: `012-corridor-path-discovery`

**Created**: 2026-11-19

**Status**: Clarified

**Input**: User description: "New system feature that is about gradually discovering the path of flight. When given order without specific coordinates , but instead are given instruction like: \"go check the corridor next 20meters and go back\", the drone will look around, do snaoshots  and await for edge to do analysis and give proper flight trajectory. While flying in this survey mode, drone is doing snapshots and edge is analysing them and will modify/ or give next flight trajectory instructions. This way drone can survey a coridors of different shapes and provide inteligence on them."

## Clarifications

### Session 2026-11-19

- Q: How should the drone execute its initial look-around sweep at the starting point and progress along edge-discovered trajectory segments? → A: Full 360-degree initial yaw sweep across discrete headings while hovering at the starting point, followed by continuous rolling flight along edge-issued segments with periodic in-flight snapshots (holding only when reaching a cleared-segment boundary or when the edge requests a pause to confirm a sharp turn).
- Q: When the drone encounters a corridor intersection/branch or detects an ordered target/hazard mid-corridor, how should edge autonomy and operator Human-in-the-Loop (HITL) control interact? → A: Fully autonomous survey with logged intelligence — the edge autonomously selects the primary open passage at intersections and continues to the full ordered distance even after spotting objects or hazards (without blocking on HITL pauses mid-corridor), logging all unexplored branches and detections with snapshots in the Corridor Intelligence Report.
- Q: How should commanders submit coordinate-free corridor survey instructions and view the resulting corridor intelligence? → A: Unified SMEAC order flow + live corridor visualization & report — commanders submit coordinate-free corridor survey instructions through the existing SMEAC order intake without requiring map coordinates, and the operator dashboard renders both live relative corridor path progress with snapshots and the final Corridor Intelligence Report.
- Q: What responsiveness target should govern edge snapshot-to-trajectory updates, and how long should the drone hold at a cleared-segment boundary before triggering failsafe return if edge guidance stops arriving? → A: Tight low-latency loop — the edge system delivers updated or next trajectory instructions within 500 milliseconds of snapshot receipt, and if no valid update arrives within 5 seconds while holding at a cleared-segment boundary, the drone automatically initiates failsafe return along the verified corridor path (or holds safely with an operator alert if return cannot be guided).
- Q: How should end-to-end verification prove gradual corridor discovery, shape adaptation, reverse-path return, and intelligence reporting across corridors of different shapes under the project's zero-mock production standard? → A: Live no-mock end-to-end verification using multi-shape corridor visual feeds — stream corridor visual sequences representing varied corridor shapes (straight, L-turn, curve/S-bend, dead-end) through the live camera, edge analyzer, flight controller, and operator dashboard to verify real edge-issued trajectory changes, reverse-path return, and the Corridor Intelligence Report.
- Q: Should gradual corridor path discovery operate at a fixed cruise altitude (2D horizontal path discovery) or dynamically adjust altitude for vertical corridor geometry (low overhangs, slopes, multi-level passages)? → A: 3D altitude-adaptive corridor navigation — the edge dynamically adjusts flight altitude during discovery and return to pass under low overhangs or follow sloped and multi-level passages, recording full 3D corridor geometry and vertical elevation profiles.
- Q: How should the drone respond if a commander intervenes to recall or abort a corridor survey mid-flight while the drone is deep inside a winding 3D corridor? → A: Two-tier Recall + Emergency Hold — a normal operator recall immediately ends outbound discovery, safely retraces the verified 3D corridor path back to origin, and publishes a partial Corridor Intelligence Report; a separate emergency abort immediately stops flight and holds safely in place (with operator alert and partial intelligence preserved).
- Q: When a corridor survey order is submitted against a multi-drone swarm (or specifies more than one drone), how should the system assign drones to explore the unknown corridor? → A: Single lead scout + staging hold — the system assigns one designated lead scout drone from the swarm to execute the 3D corridor survey while any remaining swarm drones hold safely at the staging/entrance point.
- Q: Which snapshots captured during look-around, outbound discovery, and return flight should be persisted long-term and included in the Corridor Intelligence Report and audit trail? → A: Persist every captured snapshot — store and attach all periodic snapshots captured across initial look-around, outbound flight, and return flight for complete frame-by-frame forensic replay; data retention TTL and snapshot cleanup/purging policies are explicitly out of scope for this feature (handled separately by PMDL lifecycle rules or a future ISC cleanup feature).
- Q: How should the system validate requested survey distances (e.g., extreme or invalid values like 0 m or 500 m) and constrain the vertical altitude envelope during 3D altitude-adaptive corridor flight? → A: Endurance-bounded only (no fixed upper distance cap) — reject non-positive distances, allow any positive requested survey distance relying on real-time safe-return endurance reserve to initiate early return when battery margin is reached (defaulting omitted distance to 20 meters), and enforce configurable minimum floor and maximum ceiling altitude bounds for 3D corridor flight.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Coordinate-Free Survey Order & Initial Look-Around Discovery (Priority: P1)

An operator or commander issues a natural-language mission order without explicit coordinates or waypoints, such as *"go check the corridor next 20 meters and go back"*. The system recognizes this as an adaptive corridor survey order, extracts the requested survey distance and return directive, and places the assigned drone into survey mode at its starting point. Before advancing down any unknown passage, the drone performs an initial 360-degree yaw look-around sweep across discrete headings to capture panoramic visual snapshots of its surroundings and holds safely while awaiting analysis from the edge system. Only after the edge system analyzes those snapshots and provides a validated initial flight trajectory does the drone begin flying into the corridor.

**Why this priority**: This is the foundational entry point for gradual path discovery. Without coordinate-free order interpretation and mandatory look-around validation prior to forward movement, the drone cannot safely initiate exploration in unmapped environments.

**Independent Test**: Issue a coordinate-free order (*"go check the corridor next 20 meters and go back"*), confirm the drone enters survey mode at its starting point, performs an initial 360-degree yaw look-around sweep capturing panoramic snapshots, remains in a safe hold until edge analysis finishes, and begins moving only along the edge-issued initial corridor trajectory.

**Acceptance Scenarios**:

1. **Given** an operator submits a coordinate-free mission order through the SMEAC order intake containing a survey intent, distance (*"next 20 meters"*), and return instruction (*"go back"*), **When** the system processes the order, **Then** it accepts the order in adaptive corridor survey mode with the target distance and return behavior configured, without requiring pre-defined map coordinates or waypoints.
2. **Given** a drone has received an adaptive survey order and is positioned at the mission starting point, **When** survey mode activates, **Then** the drone holds safely in place, executes an initial 360-degree yaw look-around sweep across discrete headings to capture panoramic visual snapshots, delivers them to the edge system, and refrains from forward travel until an initial trajectory is received.
3. **Given** the edge system analyzes the initial look-around snapshots and identifies a clear navigable corridor opening, **When** the edge system computes and returns a validated initial trajectory aligned with that opening, **Then** the drone initiates flight along the authorized trajectory.
4. **Given** the edge system analyzes the initial look-around snapshots and determines that no navigable corridor opening exists at the starting location, **When** edge evaluation completes, **Then** the edge system withholds any advancing trajectory, keeps the drone holding safely at the starting location, and notifies the operator of an impassable start condition.

---

### User Story 2 - Iterative In-Flight Snapshot Analysis and Adaptive Trajectory Discovery (Priority: P1)

While flying continuously in survey mode along each authorized trajectory segment, the drone periodically captures forward and surrounding visual snapshots and sends them to the edge system. The edge system analyzes incoming snapshots relative to prior corridor progress to adapt to arbitrary corridor geometries—including straight hallways, gentle curves, sharp right-angle turns, S-bends, narrowing or widening passages, low overhangs, and sloped or multi-level passages—and dynamically modifies the active trajectory or issues the next incremental trajectory segment. Whenever the drone reaches the end of its currently cleared trajectory segment before a subsequent trajectory arrives, it decelerates and holds safely (capturing additional look-around snapshots if needed) rather than flying blindly into unverified space.

**Why this priority**: Equal priority to User Story 1 because closed-loop, incremental trajectory refinement during flight is the core mechanism that enables safe traversal of corridors whose shapes are unknown at launch.

**Independent Test**: Run a survey mission inside a non-straight corridor (such as a curved passage or an L-shaped corner) without supplying any turn coordinates; stream snapshots from the drone to the edge system during flight and verify that the edge system dynamically modifies or issues subsequent trajectory segments that track the corridor's turns and clearance until the ordered distance is reached.

**Acceptance Scenarios**:

1. **Given** a drone is flying in survey mode along an authorized corridor segment and captures in-flight snapshots showing the passage continuing ahead, **When** the edge system analyzes those snapshots, **Then** it confirms clearance and issues an updated or next incremental trajectory segment extending progress toward the ordered distance.
2. **Given** incoming in-flight snapshots reveal a curve, bend, or corner in the corridor, **When** the edge system evaluates the new corridor geometry, **Then** it dynamically modifies the active flight trajectory (and may command a brief pause and look-around sweep if additional visual confirmation is needed) to steer smoothly along the turning passage while maintaining wall clearance.
3. **Given** a drone reaches the boundary of its currently authorized trajectory segment before the edge system delivers the next trajectory instruction, **When** the segment boundary is reached, **Then** the drone decelerates and holds safely while capturing fresh snapshots until the next validated trajectory arrives, never flying into unverified space.
4. **Given** a corridor narrows, widens, changes ceiling/floor elevation (such as a low overhang, ramp, or multi-level transition), or contains minor interior obstructions along its length, **When** the edge system inspects incoming snapshots, **Then** it adjusts the trajectory lateral offset, flight altitude, and speed within safe 3D navigable clearance inside the corridor.

---

### User Story 3 - Distance Completion and Autonomous Return-to-Origin ("Go Back") (Priority: P2)

As outbound survey flight progresses, the edge system tracks cumulative path distance traveled along the discovered corridor and records the traversed safe corridor path from the starting point. Once the cumulative distance reaches the ordered distance (for example, 20 meters)—or when outbound discovery terminates early due to a dead end, impassable obstruction, or safe-return endurance threshold—the edge system transitions the mission to the return phase (*"go back"*) and guides the drone safely back to its origin along the discovered corridor path while continuing snapshot-based safety monitoring for newly appearing obstructions.

**Why this priority**: Completing *"go check the corridor next 20 meters and go back"* requires accurate corridor-length accounting and safe retracing through non-straight corridors where a direct straight-line return would collide with walls or obstacles.

**Independent Test**: Execute a 20-meter survey with return enabled in a bent corridor (and separately in a shorter 12-meter dead-end corridor); confirm outbound flight stops at 20 meters (or at the 12-meter dead end) and the drone safely retraces the discovered corridor path back to the starting location and reports mission completion.

**Acceptance Scenarios**:

1. **Given** an active survey mission with a 20-meter target distance and a *"go back"* directive, **When** cumulative distance along the discovered corridor reaches 20 meters, **Then** the edge system terminates outbound discovery, transitions to return mode, and issues return trajectory instructions that retrace the discovered safe corridor path back to the starting point.
2. **Given** an outbound corridor ends at a dead end or impassable blockage after 12 meters, **When** the edge system confirms no safe continuation exists, **Then** it stops outbound exploration early, records the actual 12-meter surveyed distance and early-termination reason, and guides the drone back to the origin along the discovered safe path.
3. **Given** a drone is executing its return leg along the discovered corridor path and a new obstruction enters the path, **When** return-leg snapshots detect the obstruction, **Then** the edge system modifies the return trajectory around the obstruction within corridor clearance, or holds safely and alerts the operator if the return passage is completely blocked.

---

### User Story 4 - Corridor Intelligence Capture, Reconstruction, and Reporting (Priority: P2)

Throughout initial look-around, outbound path discovery, and return flight, the system captures, organizes, and compiles corridor intelligence so operators gain actionable situational awareness of previously unmapped passages. Intelligence includes the reconstructed corridor shape and traversed path, total distance surveyed versus ordered, completion outcome, timestamped and position-referenced visual snapshots, detected structural features (turns, width changes, intersections or side branches, dead ends, obstructions), notable objects or hazards of interest, and auditable decision records linking every edge trajectory change to the snapshots that motivated it. Operators can monitor discovery progress during flight and inspect the complete Corridor Intelligence Report upon completion.

**Why this priority**: Providing structured corridor intelligence and visual evidence is the primary operational outcome of sending a drone to inspect an unknown corridor.

**Independent Test**: Complete a survey through a multi-segment corridor containing at least one turn and one notable feature or obstruction, then inspect the generated Corridor Intelligence Report and operator view to verify the presence of the reconstructed corridor path shape, distance covered, position-referenced snapshots, structural and object findings, and snapshot-linked edge trajectory provenance.

**Acceptance Scenarios**:

1. **Given** a drone is actively surveying a corridor, **When** snapshots are captured and analyzed by the edge system, **Then** live survey progress—including current phase, cumulative distance covered, estimated corridor path trace, and recent snapshots—is recorded and surfaced for operator visibility as connectivity permits.
2. **Given** a corridor survey completes normally or terminates early, **When** the operator opens the Corridor Intelligence Report, **Then** the report displays the reconstructed corridor path shape, total distance surveyed vs. requested, completion outcome, structural features (turns, width variations, side branches, dead ends), position-referenced visual snapshots, and any notable objects or hazards detected.
3. **Given** an operator or reviewer audits a completed survey mission, **When** they review the trajectory decision log, **Then** every initial trajectory, dynamic modification, look-around command, and return transition is traceable to the edge system as decision authority and linked to the specific snapshot(s) analyzed.

### Edge Cases

- **Corridor branches or intersections (forks, T-junctions, side passages)**: When snapshots reveal multiple open corridor branches at an intersection, the edge system selects the clearest primary continuation (preferring alignment with the current corridor direction or widest clear passage) to fulfill the requested survey distance, while logging each unexplored side branch—including its relative position, heading, and snapshot—in the Corridor Intelligence Report.
- **Immediate dead end or enclosed starting point**: If the initial look-around sweep finds no navigable opening in any safe direction, the edge system does not issue an advancing trajectory, keeps the drone holding safely at the origin, alerts the operator, and records a zero-distance impassable survey outcome.
- **Delayed edge analysis or interrupted drone-to-edge communication**: If the drone reaches the end of its currently cleared trajectory segment before receiving the next edge instruction, it decelerates and holds safely without extrapolating into unverified space, retries snapshot delivery for up to 5 seconds, and—if valid edge guidance does not resume within 5 seconds—automatically initiates a failsafe return along the already-verified corridor path (or holds safely with an operator alert if return guidance is unavailable).
- **Degraded visual feed or unreadable snapshots**: If snapshots are dark, motion-blurred, frozen, occluded, or visually featureless such that navigable clearance cannot be verified with sufficient confidence, the edge system commands the drone to pause and re-capture (with orientation adjustment if needed); if visual confidence remains insufficient, it aborts further outbound discovery, alerts the operator, and returns safely along the verified path.
- **Dynamic obstacles appearing ahead or behind**: If a moving or newly placed obstacle blocks the forward path, the edge system attempts a safe clearance adjustment inside the corridor or terminates outbound discovery early if impassable. If an obstruction blocks the return corridor behind the drone, the edge system holds the drone safely and alerts the operator with visual evidence rather than attempting an unsafe collision maneuver.
- **Omitted, non-positive, or long distance in the order**: If a coordinate-free survey order specifies a non-positive distance (zero or negative), the system rejects it with a clear validation error. If distance is omitted, the system defaults to 20 meters (surfaced clearly to the operator) and defaults to returning to the origin unless the order explicitly instructs the drone to hold at the far end. Any positive requested distance is accepted without a fixed upper distance cap, relying on the drone's real-time safe-return endurance reserve to terminate outbound discovery and return safely if battery margin is reached.
- **Sharply winding or looping corridors (turns exceeding 90 degrees or U-turns)**: Distance progress MUST measure cumulative traversed path length along the corridor centerline rather than straight-line distance from the starting point, ensuring winding passages are surveyed accurately to the ordered length.
- **Flight endurance or battery reserve threshold reached mid-survey**: If remaining flight endurance reaches the safe-return reserve margin before the ordered distance is achieved, the edge system proactively ends outbound discovery, transitions to return along the discovered path, and marks the intelligence report as endurance-limited.
- **Mid-survey operator recall or emergency abort**: If an operator issues a normal recall mid-survey, the edge system immediately ends outbound discovery, guides the drone back to the origin along the verified 3D corridor path, and publishes a partial Corridor Intelligence Report marked as operator-recalled. If an operator issues an emergency abort, the drone immediately decelerates and holds safely in place while preserving all corridor intelligence collected up to that point.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The system MUST accept and interpret coordinate-free spatial survey instructions (such as *"go check the corridor next 20 meters and go back"*) submitted through the existing SMEAC mission order intake without requiring map coordinates or pre-specified waypoints, extracting the survey intent, positive target survey distance (rejecting non-positive values, imposing no fixed upper distance cap, and defaulting to 20 meters when omitted), target corridor/area context, optional objects or hazards of interest, and return-versus-hold completion directive.
- **FR-002**: Upon accepting a coordinate-free survey order, the system MUST place the assigned drone into adaptive survey mode at its starting point and perform an initial 360-degree yaw look-around sweep across discrete headings while hovering, capturing panoramic visual snapshots prior to any forward advancement.
- **FR-003**: After completing the initial look-around sweep, the drone MUST hold safely in position and MUST NOT advance down the corridor until the edge system finishes analyzing the initial snapshots and delivers a validated initial flight trajectory.
- **FR-004**: The edge system MUST analyze incoming snapshots for corridor navigability, boundaries, safe lateral and vertical clearance, obstructions, and open heading directions in order to generate collision-free incremental trajectory instructions.
- **FR-005**: While flying continuously in survey mode along an authorized trajectory segment, the drone MUST periodically capture visual snapshots and transmit them to the edge system for ongoing analysis.
- **FR-006**: Based on ongoing snapshot analysis, the edge system MUST dynamically modify the active flight trajectory or issue subsequent incremental trajectory segments using 3D lateral and altitude adjustments to guide the drone smoothly through corridors of varying shapes (including straight passages, curves, angled corners, S-bends, width transitions, low overhangs, and sloped or multi-level elevation changes) without prior map or coordinate knowledge.
- **FR-007**: Whenever the drone reaches the end of its currently authorized trajectory segment before receiving a new edge trajectory instruction—or whenever the edge system requests additional visual context at a turn or junction—the drone MUST decelerate and hold safely while capturing fresh snapshots until a validated instruction arrives.
- **FR-008**: The edge system MUST track cumulative 3D path distance traveled along the discovered corridor and maintain an ordered 3D record (relative horizontal coordinates and altitude/elevation profile) of the verified safe corridor trajectory from the mission origin.
- **FR-009**: The edge system MUST terminate outbound corridor discovery upon reaching the ordered survey distance, confirming a dead end or impassable obstruction, or reaching the safe-return endurance reserve, and MUST guide the drone back to its origin along the discovered safe corridor path when a return directive is active.
- **FR-010**: During the return leg (*"go back"*), the drone and edge system MUST continue snapshot-based monitoring to bypass minor new obstructions within corridor clearance or decelerate to a safe hold with an operator alert if the return passage becomes completely blocked.
- **FR-011**: When snapshots at an intersection or fork reveal multiple navigable branches, the edge system MUST autonomously choose a single safe primary continuation without pausing for operator HITL branch selection to pursue the ordered survey distance, and MUST record each unexplored side branch (including relative location, heading, and snapshot) in the Corridor Intelligence Report.
- **FR-012**: Throughout initial look-around, outbound flight, and return flight, the system MUST compile corridor intelligence associating every captured timestamped visual snapshot, reconstructed 3D corridor path shape and elevation profile, distance surveyed versus requested, structural features (turns, width and vertical clearance/elevation changes, intersections, dead ends, obstructions), and notable detected objects or hazards with relative positions along the corridor.
- **FR-013**: The operator dashboard MUST visually render live survey progress (current phase, cumulative distance covered, emerging 3D relative corridor path shape (horizontal layout and elevation profile), and captured snapshots) during flight and present the structured final Corridor Intelligence Report (including completion status and any early-termination reason) upon mission completion.
- **FR-014**: Every edge-issued initial trajectory, dynamic trajectory modification, look-around command, and return transition MUST be logged with a timestamp, edge decision authority provenance, and reference(s) to the analyzed snapshot(s) that triggered the decision, and any operator-initiated recall or emergency abort override MUST be logged with explicit operator provenance.
- **FR-015**: If visual snapshots are degraded beyond safe analysis confidence or if no valid edge trajectory update arrives within 5 seconds while holding at a cleared-segment boundary, the system MUST halt further outbound advancement, notify the operator, and automatically initiate a failsafe return along the already-verified corridor path (or maintain a safe hold with an operator alert if return cannot be safely guided).
- **FR-016**: Adaptive corridor survey mode MUST remain fully autonomous without pausing for operator HITL confirmation upon mid-corridor target or hazard detections: unexpected hazards inside the corridor MUST be avoided or halted safely, while objects matching mission intelligence interests MUST be captured with snapshots and highlighted in the Corridor Intelligence Report as the drone continues to complete the ordered survey distance.
- **FR-017**: The system MUST support end-to-end verification without mocked edge analysis or mocked flight control using streamed multi-shape corridor visual sequences (covering straight passages, L-turns, curves/S-bends, elevation-varying low-overhang/sloped passages, and dead ends) fed through the live camera, edge analyzer, flight controller, and operator dashboard, proving real edge-issued trajectory transitions, reverse-path return, and Corridor Intelligence Report generation.
- **FR-018**: The system MUST support two distinct mid-survey operator override commands: a normal recall command that immediately terminates outbound discovery, retraces the verified 3D corridor path back to the origin, and publishes a partial Corridor Intelligence Report; and an emergency abort command that immediately halts flight into a safe in-place hold while preserving collected corridor intelligence and emitting an operator-visible status alert.
- **FR-019**: When a corridor survey order targets a multi-drone swarm (or specifies more than one drone), the system MUST assign exactly one designated lead scout drone to enter and survey the corridor while keeping all remaining swarm drones holding safely at the staging/entrance point, clearly identifying the lead scout in mission telemetry and the operator dashboard.
- **FR-020**: The system MUST persist every visual snapshot captured during the initial 360-degree look-around sweep, outbound corridor discovery, and return-to-origin flight along with its timestamp, relative 3D pose, survey phase, and edge analysis linkage to enable complete frame-by-frame forensic replay; snapshot expiration (TTL) and automated storage cleanup are explicitly out of scope for this feature.
- **FR-021**: During 3D altitude-adaptive corridor flight, the edge system MUST enforce configurable minimum floor and maximum ceiling altitude safety bounds, constraining or refusing trajectory adjustments that would violate the configured vertical envelope, while relying on real-time safe-return endurance reserve rather than a fixed upper distance cap to trigger return on long-distance orders.

### Key Entities

- **Adaptive Survey Order**: A coordinate-free mission instruction specifying survey intent, target distance (or default limit), return-versus-hold expectation, and optional intelligence focus items without explicit route waypoints.
- **Survey Snapshot**: A timestamped visual capture taken by the drone during initial look-around, outbound flight, or return flight, tagged with the drone's relative 3D position (horizontal offset and altitude), heading, and survey phase at capture time.
- **Edge Trajectory Instruction**: An incremental, edge-validated guidance command specifying safe 3D movement direction, altitude/elevation adjustment, segment distance or curve, speed and 3D clearance constraints, or a look-around/hold/return directive, linked to the snapshot(s) analyzed.
- **Discovered Corridor Path**: The ordered sequence of verified safe 3D trajectory segments, corridor width and vertical clearance estimates, turns, elevation changes, intersections, and cumulative 3D path distance recorded incrementally from the mission origin.
- **Corridor Intelligence Report**: The structured operational output compiled from a survey mission, containing reconstructed 3D corridor shape and elevation profile, distance surveyed vs. requested, completion outcome, position-referenced snapshots, detected structural characteristics, unexplored branch notices, notable objects/hazards, and auditable edge decision provenance.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: At least 95% of valid natural-language coordinate-free corridor survey orders correctly resolve into adaptive survey missions with the intended distance and return directive and enter look-around survey mode without requiring manual waypoints.
- **SC-002**: 100% of survey missions perform the initial look-around snapshot sweep and remain safely holding at the starting point until the edge system delivers a validated initial trajectory (zero unvalidated forward departures).
- **SC-003**: Across test surveys spanning straight, curved, L-shaped (90-degree turn), S-bend, and elevation-varying (low-overhang or sloped) corridors, at least 95% of runs navigate without boundary collisions and cover the ordered 3D path distance within ±10% tolerance (or reach the physical dead end when shorter than the ordered distance).
- **SC-004**: 100% of runs experiencing delayed edge trajectory updates beyond the cleared segment or encountering an impassable blockage decelerate and hold safely before entering unverified space (zero unvalidated boundary overshoots).
- **SC-005**: At least 95% of surveys with a return directive successfully retrace the discovered corridor path back to the starting area without boundary collisions, including surveys terminated early by dead ends or impassable obstacles.
- **SC-006**: 100% of completed or early-terminated surveys produce a Corridor Intelligence Report containing the reconstructed path shape, surveyed distance, position-referenced snapshots, structural and hazard findings, and complete snapshot-linked edge trajectory provenance within 5 seconds of mission end.
- **SC-007**: Under nominal link conditions, at least 95% of in-flight survey snapshots yield an edge trajectory update within 500 milliseconds of snapshot receipt, and in 100% of edge-guidance outages exceeding 5 seconds at a cleared-segment boundary, the drone initiates failsafe return (or safe hold with operator alert) within 5 seconds.

## Assumptions

- **Relative Local Navigation Availability**: Drones operating in enclosed or satellite-denied corridors can measure relative 3D movement (horizontal displacement and altitude), heading, and cumulative traversed path distance with sufficient local precision to execute incremental trajectory segments and retrace the discovered path back to the origin.
- **Single Lead Scout Assignment in Multi-Drone Swarms**: Each coordinate-free corridor survey order assigns one designated lead scout drone to enter the corridor (with isolated vision, 3D trajectory state, and intelligence reporting), while any other drones in the same swarm hold safely at the staging/entrance point to prevent confined-space collisions.
- **Autonomous Branch & Detection Handling**: During an exploratory corridor survey, the edge autonomously selects the primary continuation at intersections and continues completing the ordered distance after spotting targets or hazards (logging all unexplored branches and detections with snapshots) rather than pausing for mid-corridor operator HITL decisions.
- **Distance Defaults & 3D Vertical Safety Bounds**: When an order omits an explicit distance or return instruction, the system defaults to 20 meters and return-to-origin upon completion; any positive requested distance is permitted without a fixed upper distance cap (bounded in flight by real-time safe-return endurance reserve), while 3D altitude adjustments remain constrained within configurable safe floor and ceiling bounds.
- **Reverse-Path Return Safety**: Returning to the origin always retraces the verified discovered corridor path in reverse rather than attempting a direct straight-line return-to-home path that could intersect corridor walls.
- **Minimum Visual Navigability**: Corridors provide adequate visual contrast and illumination (or onboard illumination) for the drone's camera to capture analyzable snapshots; when visual confidence is insufficient, fail-safe hold or return governs behavior.
- **Edge Compute Authority**: Low-latency snapshot analysis and incremental trajectory generation run on the edge node closely coupled to the drone, while live progress updates and compiled Corridor Intelligence Reports synchronize to central command-and-control as link quality permits.
- **Framework Governance Alignment**: The iterative *look-around → snapshot → edge analysis → incremental trajectory* cycle follows the project's continuous Observe-Orient-Decide-Act (OODA) execution model and Long Term Vision of intent-driven autonomous swarm operations.
- **Multi-Shape Corridor Verification Media**: End-to-end zero-mock verification streams deterministic corridor visual sequences representing straight, curved/S-bend, L-turn, elevation-varying (low-overhang/sloped), and dead-end geometries into the live camera, edge analyzer, flight control, and operator dashboard pipeline without stubbing edge decision-making.
- **Snapshot Retention & Cleanup Out of Scope**: Every visual snapshot captured during a corridor survey is persisted in full without pruning; time-to-live (TTL) retention enforcement and automated cleanup/purging are handled outside this feature's scope.
